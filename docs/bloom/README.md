# The platform graph, in Neo4j Bloom

Generated by `pf bloom build`. **Do not edit** — regenerate, or these files will
disagree with the graph they claim to describe.

Eight projects each build a knowledge graph and none can see the others, which
is right while you are working on a project and useless when the question spans
the estate. This is all eight, unioned: **13,376 nodes and 14,399 relationships**.

## Load it

1. Copy `nodes.csv` and `edges.csv` into your database's `import/` directory
   (Neo4j Desktop: **⋯ → Open folder → Import**; Aura: use a public URL and
   change the `file:///` prefix in `load.cypher` to it).
2. Run `load.cypher` in Neo4j Browser or `cypher-shell`. It is idempotent —
   a unique constraint on `id` means re-running updates rather than doubles.
3. The last statement prints the counts. They must match the numbers above; a
   short count means rows were rejected and the log says which.
4. In Bloom: **Perspective → Import** and choose
   `data-platform.bloom-perspective.json`.

APOC is required for the relationship load, because the relationship type is
data and Cypher cannot parameterise one. It ships with Desktop and Aura.

## What you get

The perspective is the half that matters. Without it Bloom renders grey circles
captioned by whichever property comes first, and 13,376 nodes drawn that way is
noise.

**Colour is the plane**, the same three the KG Atlas uses — teal for the
physical and analytical layer, violet for the semantic one, slate for
governance. Shade within a plane tracks containment: a Project is darker than
the Models it holds, a Model darker than its Columns.

**`Column` is hidden by default.** It is 10,444 of
13,376 nodes — 78% — and any view
containing it is unreadable. One click in the category list brings it back.

**Ten saved search phrases**, each a question somebody has had to answer by
reading files:

- **What breaks if I change $model**
- **Who consumes column $column**
- **Where $concept is instantiated, in every project**
- **Everything policy $policy governs**
- **Marts no policy governs**
- **Models with no test**
- **Physical tables that instantiate no concept**
- **What feeds exposure $exposure**
- **One name, two projects — check they mean the same thing**
- **Policy to evidence, end to end**

## Ids are qualified, on purpose

`Model:orders` exists in `acme-us` and in `acme-eu`, and they are different
models. Merging on the bare id would weld two sisters' lineage together —
exactly what the isolation rule exists to prevent. Every node id here is
`group/project#local_id`, and the original is kept as `local_id` so a Bloom
result can still be traced back to the project graph it came from.

## Modelled on

[`neo4j-graph-examples/bloom`](https://github.com/neo4j-graph-examples/bloom) —
a loader plus one `.bloom-perspective.json`. Three departures, each deliberate:

| | reference | here | why |
|---|---|---|---|
| data | `data/*.dump` | CSV + Cypher | a dump is unreviewable in a PR, and needs that exact Neo4j version |
| ids | bare | `group/project#id` | eight graphs share an id space; merging fuses sisters |
| props | typed columns | flattened JSON | Neo4j cannot nest; dropping loses more than stringifying |
