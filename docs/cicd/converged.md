# `converged` — is the committed tree still what the generator produces?

**Workflow:** `.github/workflows/platform.yml` · **Job:** `converged`

## In one paragraph

A large part of this repo is **generated**: context cards, the eleven per-project
CI workflows, `platform.yml` itself, vendor docs, per-project maps. This job
runs the generator on a clean checkout and fails if regenerating changed
anything that is committed. It answers one question: **is what is checked in
still what the generator produces?**

## How it works — two steps

```bash
uv run pf bootstrap --all        # regenerate every generated file, all 11 projects
git diff --exit-code --ignore-submodules=dirty -- . ':(exclude)…'
```

`git diff --exit-code` exits 1 if anything changed. The long list of
`:(exclude)` pathspecs covers files that legitimately differ run to run
(`**/kg/graph.json`, `**/reporting/**`, `**/HARNESS.md` and others).

So the rule is: **regenerate, and if that edited a committed file, you are
behind the scaffold.**

## What you see when it fails

```
diff --git a/docs/VENDOR-CARD.md b/docs/VENDOR-CARD.md
-| `pr-agent` | ... | shape | ok    |
+| `pr-agent` | ... | shape | drift |

::error::pf bootstrap --all changed tracked files, so the
::error::committed tree is behind the scaffold. Run it
::error::locally and commit what it writes.
```

## Worked example — the real one, from this branch

Someone bumped four vendored pins (`git submodule update --remote`) and
committed the moved gitlinks. `docs/VENDOR-CARD.md` is generated by
`pf vendor docs` and records each upstream's drift state. Moving the
`pr-agent` pin flipped its row from `ok` to `drift` — but the card was never
regenerated, so the committed card described a state that no longer existed.

**Fix:**

```bash
uv run pf vendor docs
git add docs/VENDOR-CARD.md docs/VENDOR.md
git commit -m 'fix(vendor): regenerate the vendor card after the pin bump'
```

## The part worth understanding

**This job does not watch `vendor/**`.**

Its path filter (`platform.yml:12-18`) lists `platform/**`, `pyproject.toml`,
`uv.lock`, `gate.yaml`, `groups/*/group.yaml` and `platform.yml`. A commit that
only moves submodule gitlinks touches `vendor/<name>` and nothing else — so it
matches no filter and **the job that would have caught the stale card never
ran.**

It only failed later, when an unrelated change to `platform/**` woke the job
and it found the card had been stale the whole time.

That is the failure mode to take from this page: **a gate with a path filter
only catches what wakes it.** The stale file was committed by one change and
reported against another.

## Never hand-edit a generated file

| File | Who writes it |
|---|---|
| the eleven `<project>.yml` | `pf bootstrap`, from each capability's `ci_jobs` |
| `platform.yml` | `pf bootstrap`, from `PLATFORM_WORKFLOW` in `pf.scaffold.bootstrap` |
| everything else in `.github/workflows/` | by hand |

Hand-editing a generated workflow is silently undone by the next
`pf bootstrap`, and this job fails on the difference. `gate.yaml` denies
`.github/workflows/**` to agents for exactly that reason.

## Reproduce locally

```bash
uv run pf bootstrap --all
git status          # commit whatever it wrote
```
