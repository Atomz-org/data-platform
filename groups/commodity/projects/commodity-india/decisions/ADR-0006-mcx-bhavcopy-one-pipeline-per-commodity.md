# ADR-0006: MCX's own bhavcopy lands as one dlt pipeline per commodity

**Status:** accepted · 2026-09-25

## Context

Until now this project priced India only from international benchmarks landed
through FX and duty (ADR-0005); `fct_mcx_lot_equivalents_daily` sizes those
landed prices to MCX lots but holds no MCX quote. A desk trades against what MCX
itself settled, so the exchange's daily bhavcopy — every futures contract and
option strike with OHLC, settlement, volume, open interest and turnover — is
now a source, with the trading metrics computed on it and a report per
commodity.

Two community libraries wrap MCX, and the request named both: `mcxlib` 0.4
(RuchiTanmay, MIT) and `mcxpy` 0.0.3 (Tapanhaz, MIT; its README calls itself
experimental and for education). On 2026-09-25 **neither works**: both POST to
`https://www.mcxindia.com/backpage.aspx/<Method>`, which MCX retired in its
Sitefinity redesign — every such route returns MCX's own 404 page, and the
Excel reports mcxlib reads under `/docs/` return 403. The data moved to
`GET /market-data/bhavcopy/GetDateWiseBhavCopy` and
`GET /market-data/bhavcopy/GetCommoditywiseBhavCopy` (same JSON records), and
Akamai in front of it admits mcxlib's browser header profile while refusing a
bare User-Agent. The contract list is embedded in the bhavcopy page as
`div#symbol-data`.

## Decision

1. **Connector** — `commodity_india/mcx_feed.py`, in this project, not in
   `commodity_shared`: MCX is India's exchange, a market fact like
   `mcx_contract_lots`, and no sister would call it.
   * `contract` strategy (default): `GetCommoditywiseBhavCopy` per contract via
     dlt Core's `RESTClient`, with mcxlib's header profile. One request returns
     a contract's whole life; a daily run is a handful of requests.
   * `datewise` strategy: one bhavcopy per day, trying `mcxlib` → `mcxpy` →
     direct and keeping the first that answers. The libraries' own API, kept so
     they are used again, unchanged, the day they follow MCX's move.
   Both libraries are project dependencies. Rows record `extracted_via`.
2. **One commodity, one pipeline, one asset, one job.** The `mcx_products` seed
   files every MCX code under a commodity (GOLD, GOLDM, GOLDTEN, GOLDGUINEA,
   GOLDPETAL → `gold`). Each commodity runs its own dlt pipeline
   (`commodity-india_mcx_<c>`), so cursors and failures are per commodity, into
   one `mcx` dataset of three tables (`futures_bhavcopy`, `options_bhavcopy`,
   `contract_master`). In Dagster an asset factory makes one asset per commodity;
   the three tables are one `mcx_landed_tables` step that every commodity feeds
   and that verifies what landed — the keys the dbt sources resolve to. Each
   commodity's job is its whole pipeline: its load, that verification, the MCX
   dbt models and tests, and the Evidence build. Schedules are staggered and
   paused or resumed in Dagster at any time;
   `src/commodity_india/defs/mcx_jobs.yaml` sets the state they are created in.
3. **Resumable loads.** Batches of `max_contracts_per_batch` contracts, each a
   committed load with its cursors. A stopped run loses at most one batch.
4. **Vocabulary** — `ExchangeContract` (a Product) and `ContractSession` (an
   Event) with three relations, in the *group* ontology: nothing about a
   futures contract is MCX's, and a CME sister would use the same words.
5. **Layering.** Staging is generated (`pf gen-staging`) into `staging/mcx/`;
   intermediate models live in `intermediate/mcx/`. Both are paths the family
   compares byte-for-byte across sisters, so the group test now exempts the
   directories of a market-local source — one named in a sister's annotations
   that no group connector provides — and nothing else.
6. **Metrics in marts, not pages.** `fct_mcx_commodity_daily` computes every
   indicator on a roll-free, ratio back-adjusted series of the most-active
   contract (highest OI). Recursive indicators (EMA, MACD signal, Wilder RSI and
   ATR) are an exact `with recursive`, not a window approximation, and portable
   to Snowflake.

## Consequences

* MCX's terms of use govern automated access to its website. Requests are
  spaced (`pause_seconds`) and a daily run is small, but production use is a
  decision for the desk, not for this pipeline.
* If MCX moves the routes again, `MCXUnavailable` names the route; the seed
  and every commodity job fail loudly rather than build marts over nothing.
* `mcx_products` specifications were derived from the bhavcopy itself; four
  illiquid codes carry published specs flagged `is_spec_verified = false`, and
  `assert_mcx_unverified_specs_hold` warns with the evidence to correct them.
* The Evidence home page is regenerated by `pf report build`, so the MCX
  summary is the report's own home at `/mcx`, with `/mcx/<commodity>` per
  commodity.
